## 一、项目是什么

把大语言模型接入即时战略游戏《铁锈战争》（Rusted Warfare）：
Java javaagent 挂游戏 JVM 实时提取战况（快照/NDJSON/TCP 41234），Python 桥接层决策，指令经游戏原生命令队列回注。
**仅限单机研究，严禁多人对战。**（RW 本体 libRocket 鼠标处理有 latent bug，与 agent 无关，已鉴定）

## 二、架构（v3.2 当前生效形态）

```
LLM 层（DeepSeek，事件触发，非轮询）：
  总指挥（v4-pro）：《作战计划书》五小节文本 + ```json 参数块（阶段/池数/建造者数/厂型/主攻/防线/姿态）——机器消费，不靠子层猜
  建造指挥（v4-pro）：《建造工单》JSON——任务序列(slot 规格或坐标)+防线点位(坐标级)+建造者目标数；建造 chat 已退役
  战斗指挥（v4-flash）：《小队任务书》JSON——S1~S4 编号（系统分配+校验）attack/defend/hold/harass/produce
  squad chat ×N（v4-flash）：每编号小队一个循环，上下文=本队任务+本队态势+自己最近4条动作，只做快速反应
确定性层（零 token）：
  BuilderManager（executor 内嵌 2s/拍）：工单调度——按序派任务、buildq 拉条、完成推进、90s 烂尾重派
  规则快层（executor routine）：采集器补给/工厂扩建升级/防线网格弧/池点哨戒/抢修/重建/判死黑名单（全自主，无需 LLM 确认）
  小队管理器（multiagent 2s/拍）：归队（编成提示匹配+最小队优先）/produce 刻度（照单 train）/按任务开 squad chat 线程
  反射层 reflex（毫秒级，分小队）：受击撤退按小队独立；基地回防只拉守家队（进攻队不动）；建造者赴险召回（防线圈豁免）
  领土控制图 powergrid：战力标签（dps×hp/100 分对地/对空）+ 400px 格安全值/占领状态/安稳判定
游戏内 UI（agent 内嵌）：AI 聊天台（可打字）/委托面板/设置面板（三角色开关）/主栏
```

**核心方法论**：LLM 出计划/工单/任务书（JSON），确定性层按拍执行，事件决定何时召唤 LLM。
模型分路（config.toml）：commander_model/build_model=deepseek-v4-pro、combat_thinker_model/combat_squad_model=deepseek-v4-flash（id 经 /v1/models 核实）。
关键开关：`build_chat_enabled=false`（建造 chat 退役）、`auto_production=false`（规则层不自动产兵，产量归战斗指挥 produce 条目）。
历史实测耗时（tools/analyze_pace.py）：chat 单轮 42~48s、commander 112s、轮询制有效吞吐仅 ~2.8 动作/分钟——事件触发+宏微分离的直接动机。

## 三、怎么跑起来

1. `bash agent/build.sh`（JDK 11+，自动下载 ASM shade）
2. `bridge/secret.toml` 填 DeepSeek key
3. `rw-ai.bat`（一键：游戏+桥接）；`tools/run-bridge.bat` 只重启桥接（不动游戏）
4. 游戏内开遭遇战 → 点 overlay「全队接管」→ 聊天台可直接打字指挥
5. 数据面：`bridge/activity.jsonl`（活动流）、`bridge/pilot.log`（LLM 调用时序/并发）、`tools/match_metrics.py`（对局度量，存 metrics_history.jsonl）、`tools/analyze_pace.py`（耗时分析）
6. **监控面板（总控台）**：桥接起来后浏览器开 <http://127.0.0.1:8321>——第一屏=三角色在想什么（计划书全文+参数/建造工单进度/小队任务书）+战况一行+活动流；可发高层指令（与玩家留言同优先级）；三角色启停开关（覆盖游戏面板，可恢复跟随；`config.toml` 的 `dashboard`/`dashboard_port` 可关可改端口）
